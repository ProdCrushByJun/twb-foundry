# Procedure: HTML dashboard + CSV → spec.json

The goal: a spec that reproduces the dashboard within what the generator can do, **without a single unverified mapping**. Whatever does not move 1:1 goes to the report; it is not guessed.

## 0. Input
- An HTML dashboard (a local file) and the CSV with the data it is built on.
- If there is no CSV, stop and ask. Do not make data up "from the HTML".
- Instead of a CSV, an `.xlsx`: one table on a sheet, the header in row 1 from A1. `profile <data.xlsx>` without `--sheet` lists the sheets; choose a sheet by the data and pass `--sheet <sheet>` to `profile` and `analyze`. In the spec: `"datasource": {"type": "excel", "path": "...xlsx", "sheet": "<sheet>"}`. If `profile` refuses (a report title above the table, several tables, merged cells, mixed types, formulas without values), do not silently fix the file: ask for a clean export or, with the user's consent, save the needed sheet as a separate file and write that in the report.
- Several independent data sets (HTML tabs on different exports, a main set + opportunities): do not glue them into one CSV: `"datasources": [{"name": "main", "type": "csv", "path": "main.csv"}, {"name": "opportunities", ...}]` instead of `datasource`, a sheet has `"datasource": "<name>"` (the first by default), a calc too. A filter goes with the source of its `show_on`, an action filters only sheets of its source; no blending or relationships. `profile` and `analyze` per file.

## 1. Facts (deterministic)
```bash
python -m tbuilder profile <data.csv>
python -m tbuilder analyze <page.html> <data.csv> -d out/<name>
```
The result in `out/<name>/`:
- `page.png`: how the page looks;
- `outline.json`: blocks (`kpi`, `bars`, `svg`, `table`, `list`, `image`, `canvas`), their titles, frames, the `layout` tree, palette, controls; a `table` also has its header color (`header_colors`) and the color of bars in cells (`bar_colors`);
- `evidence.json`: field candidates for each block. KPIs are matched by the number equal to an aggregate (with `where` for categories and unit conversion `÷1000`), category blocks by labels equal to a column's values.

`outline.json` has `profile` if the mock is drawn in a profile's style (the `tb profile-css` block): write it to `spec.profile`.

You must look at `page.png`. The outline says *where* the blocks are, the picture says *what* chart it is.

On hand-made pages the outline finds few blocks (`layout` = `overlap`, KPI tiles and panels not recognized). Then take blocks, titles (`outline.headings`), layout and numbers (`outline.texts`) from the DOM and `page.png`, and read the page's scripts: what is selected on load, what recalculates by a filter, what labels JS generates. The rule "a field by evidence only" still holds: `reconcile` gives the evidence for such numbers (matched / mismatch), so run it right after the first build (§4), not at the end.

## 2. Mapping blocks (rules)

| Outline block | Condition | In the spec | In the report |
|---|---|---|---|
| `kpi` | a candidate **without** `where` and `unit` | a measure in the KPI sheet (`agg` from the candidate), `label` = the card's label in the HTML | — |
| `kpi` with a unit after the number ("40.2 h", "35 min", "2.4x": the block has `unit`) | the measure is a calc or a candidate | measure, `label` = label + ", <unit>" ("Mean time to resolve, h"): reconcile matches the number with this tile | — |
| `kpi` | the best candidate has `unit` (`÷1000` etc.) | a measure with this `agg` | "the value will be in source units (kW instead of MW); unit conversion is not supported" |
| `kpi` | candidates with `where` only (a KPI by category) | a group of such KPIs → **bar** (`dimension` = the field of `where`, `measure` = the candidate) | "KPIs by category gathered into one bar" |
| `kpi` | no candidates | do not move | "the number cannot be reproduced from the data" + the number |
| `bars` horizontal/vertical | `label_candidates[0].coverage` ≥ 0.5 | bar: `dimension` = this field, `orientation`; measure from the numbers on or near the bars (through evidence), else ask | — |
| `bars` stacked (one strip of segments) | labels match the categories | a bar by this category; shares → the total measure | "the share (%) is shown in absolute values; stacked-100% is not supported" |
| `bars`/canvas bars with periods on the axis (Jan…Jun, Q1…Q4, years), stacked too | a **date** field in the CSV | bar: `dimension` = the date, `date_level` by the axis labels, `orientation: vertical`, `color` = the segments' field | plan / top / reference / highlight of a bar by date → "not moved" |
| `svg` line with years/dates on the axis | a **date** field in the CSV | line (`level` by the axis labels: year/quarter/month) | — |
| `bars`/`svg` with years | the year is an **integer** column | do not move | "a numeric field as a time axis is not supported (no golden)" |
| `svg` with `paths` and dates on the axis | a date field | line | — |
| `svg` with **filled** paths (area, `fill` ≠ none) and dates on the axis | a date field | area (`color` = the layers' category, if any) | — |
| `table` with cells colored by value (a background gradient) | as for table | heatmap(rows=A, cols=B, measure, color: {scale}) | — |
| `bars` + a line of a second measure on top (two axes / a second scale on the right) | a category field on the axis | combo(dimension, bar, line; `sort` by the bar), a dual axis: gray bars with numbers, an accent line, its axis hidden, axes synchronized for one unit | bars by date / "above average in color" / a dashed line in a combo do not exist yet → "not moved" |
| `svg` donut with a number in the center, a legend "value (share)" | ≤ 5 values of the field (more: lint C2 warn: lollipop or bar) | donut(dimension, measure): the total in the center and a legend sheet next to it are generated | a plain pie without a hole is shown as a donut |
| `svg` lollipops: a thin stick + a circle with a number | a category field | lollipop(dimension, measure, `sort`), horizontal | a vertical lollipop → horizontal |
| `svg` dots on two axes (scatter; crossed dashed lines "Avg: 17.8" / "Avg: $11,899") | two measures per dot and a dimension the dot stands for | scatter: `detail` (the dot's dimension), `x`, `y` (measures); dashed averages on both axes → `axis_lines: {label: "Avg:"}` (medians → `type: median`); one highlighted dot → `color: {highlight: [members of detail]}` + `{accent:…}` in the subtitle; color by a field → `color: "<dimension>"` (dots become detail × color) or `color: {field: <measure>}`; size → `size`; a trend line → `trend: true` | a double circle with a halo (a dual axis of the same dots) → one dot with a white outline; dot labels are not moved (the name in the tooltip) |
| `svg` map (paths of countries/states, d3-geo, topojson) or a leaflet / mapbox container | the CSV has a field of countries / US states (etc.), or latitude and longitude columns | map: circles by measure size → `geo: {field, role: country\|state, country?}`, `measure`; a color fill → `style: filled` (country / state only); points by coordinates → `geo: {field, lat, lon}`. For state, `geo.country` is required ('United States'). The color of circles / fill by a measure → `color: {scale: sequential|diverging, center?, good?, steps?, min?, max?}`, as in a heatmap; color by a second measure (size one, color another) → `color: {…, measure: {field}}`; circles of one size, the measure in color only → `size: false` (symbol); filled can have `scale: diverging` with `center` too. Names Tableau does not know are a build error with a hint: fix the data | a city by name (`role: city`): lint G2 error: Desktop does not find same-named cities in different states → states or lat / lon; background tiles, base layers, an own Mapbox style → "background: Tableau Light" |
| `table` / `list` | rows = values of field A, there is a second category field B for columns | table(rows=A, cols=B, measure) | — |
| `table` / `list` | one category field only | bar(dimension=A, measure by the rows' evidence) | "a table of one dimension is shown as a bar" |
| `image`, `canvas` (a raster map without place data, a raster chart) | — | do not move | "map/image: not supported" |
| `controls` (select/buttons) | `label_candidates` coverage ≥ 0.5 | `filters`: field + `show_on` = the nearest sheet; opens at "(All)", new values in the data are visible too. **A select / preset with a selected value in the HTML → `default: [values]`** (the book opens with the same selection); `<select>` without multiple → `mode: "single_dropdown"` (one default); a cascade (the list of cities depends on the region) → `relevant: true` on the dependent one; "all except X" → `default: [X]`, `exclude: true`; Top N / FIXED "within the selected" (top 10 in a region) → `context: true` on this filter; **a filter changes not all blocks** (the page's script recalculates one table, the rest stand) → `sheets: [the sheets it changes]`, `show_on` is one of them; on several tabs without `sheets` a filter acts on its own tab | default values exactly as in the data; if all are selected, no default |
| `controls`: a select **preset** (option labels are not data values: "East — Boston, Back Bay (was XD-0002)") | `candidates` coverage ≥ 0.5 | the field is the evidence candidate, the value is the member the option names (`East`). The option selected on load: `controls[].selected` (`page.png` shows it too); an "All …" option → no `default`. `multiple: false` → `single_dropdown` | if a preset is a set of members no single field has: a filter by the members' field with `default` of all the preset's members, and a question to the user |
| `controls`: a "filter" plate without a control ("Period: Current week" as text) | no date field in the data | do not move; the period can be named in the block's `subtitle` | "a static period plate: no date in the data" |
| `controls`: a date choice (`input type=date`, "from — to", a date picker) or period buttons ("7D / 30D / 3M / YTD", "Last 12 months") | the CSV has a date/datetime field | `filters` with `mode: "range"` or `"relative"` (rule 8a) | — |

Where evidence is in `evidence.json`:
- `kpi.candidates`: field and agg, plus `where` if the KPI is counted by category;
- `bars.candidates`: the dimension field; `bars.value_candidates`: the measure by the numbers at the bars;
- `table.row_candidates` / `col_candidates` / `cell_candidates`: fields of rows and columns, the cells' measure (`where` with AND);
- `svg.candidates`: the date column and level (month/quarter/year/day) by the axis labels;
- `control.candidates`: the filter's field.

General rules:
- **Derived KPIs → `calcs`.** A ratio (Profit Ratio = SUM/SUM, rates, conversions) → an aggregate calc, `format: "percent"` for shares, a measure without `agg`. A KPI "by category" (Incidents closed = only rows Type=Incidents) → a row-level calc `IF [Type] = "Incidents" THEN [Closures] END` + a plain SUM, instead of folding into a bar. Grouping values into buckets (Large/Medium/Small) → a string calc as a dimension. Syntax: only the subset in `tbuilder/formula.py`; unsupported → the report.
- **Formula functions**, semantics checked against Desktop 2025.1:
  - logic: `IIF(cond, yes, no [, unknown])`, `IFNULL(x, replacement)`, `ISNULL(x)`, `[Region] IN ("East", "West")` (literals only in the list);
  - dates: `DATEDIFF('day|week|month|quarter|year', start, end)`, `DATEPART(...)`, `DATENAME('month'|'weekday', date)`, `YEAR/QUARTER/MONTH/DAY/WEEK`. Names from DATENAME are **English** ("Wednesday", "December") in any workbook locale. `DATEPART('weekday')` counts Sunday = 1 whatever the week start; `WEEK()` counts weeks from Sunday, `DATEPART('week')` from Monday (like the book). No literals like `#2024-01-01#`;
  - conversions: `STR`, `INT` (truncation to zero, a string "3.7" → 3, "abc" → NULL), `FLOAT`. **STR of a fraction prints 17 significant digits** (`STR(0.1)` = "0.10000000000000001"): only integers in labels (`STR(INT(...))`, `STR(SUM([Integer]))`);
  - strings: `CONTAINS / STARTSWITH / ENDSWITH` (case-sensitive), `LEFT / RIGHT / MID` (from 1), `UPPER / LOWER` (ß → SS), `REPLACE`, `LEN`, `TRIM`, concatenation `+`. A number to text only through `STR()`;
  - a finding line ("Busiest day: Wed (137)") = a text aggregate: a key `{INCLUDE [Day] : STR(SUM([X]) + 100000) + MIN(...)}` and `MAX(key)` taken apart with `LEFT/MID/INT`. It can be shown only in a KPI tile (`kpi` style `tiles`), as a short line, or through `insight` (below); a block's subtitle cannot hold a field (it is dashboard text). Do not move a long phrase yet → the report.
- **"% of total / of group" → a FIXED LOD**: `{FIXED : SUM([X])}` (the total) or `{FIXED [Group] : SUM([X])}`, share = `SUM([X]) / MIN([Total])`, `format: "percent"`. A group-level flag (a large region, a first order) → a row-level calc over the LOD. "Average by customers/categories within a group" → `{INCLUDE [Customer] : SUM([X])}` + `agg: avg`; "the group's total in each cell" → `{EXCLUDE [Dimension] : SUM([X])}`. INCLUDE/EXCLUDE only as a whole formula or directly inside SUM/AVG/…
- **Number format → `format` of a measure or calc.** Write it as the HTML prints the number: `match` puts a KPI's `format` from the text in the report ("$1.2M" → `{type: currency, units: M, decimals: 1}`, "634.6K" → `number_k`, "(1,234)" → `negative: parentheses`, "12.5%" → `pct1`). A format belongs to a field (its `default-format`): one field has one format across the book; a second look of the same field is a calc copy with its own `format`. A calc's format is written only in `calcs[].format`. Tableau 2025.1 has no auto units per value ($980K here, $1.2M there): choose one unit by the main number (KPI), `reconcile` shows the rest as `format`: accept with a reason.
- **A field's name as in the HTML → `fields.<column>.caption`.** The field is a code in the data (`customer_tier`, `vip_flag`, `stage`) and the HTML writes "Customer Tier", "VIP Customer", "Stage" in a table header, over a column or in a filter's label → `"fields": {"customer_tier": {"caption": "Customer Tier"}}`. Tableau shows the caption in headers, filter cards and tooltips; in the rest of the spec the field keeps its data name. The caption comes from the HTML, it is not invented: none in the HTML, Title Case of the name. Lint F1 finds header fields without a caption.
- **Labels, order, groups, member colors → `fields`.** In the HTML a member is written differently than in the data ("Mon" vs "19 Mon", "Inc" vs "Incidents") → `fields.<field>.aliases {value: label}`, otherwise `reconcile` gives `elsewhere`. A non-alphabetical order (Mon…Sun, Low/Medium/High, as on the page) → `order`: all values of the field, in page order, and a bar has `sort: none`; a text calc field too (`order` only). More than 5 colors (C2) or "Other" on the page → a group: a new field `fields.<name>.group {field, bins: {bin: [members]}, other: "Other"}`, its name in `dimension` / `color`. Category colors from the HTML (navy / blue / light) → `color {value: "#hex"}` for all values. Keys everywhere are data values (for a group, bin names), not labels. Color with a meaning (highlight, good/bad) stays in the sheet's `color`.
- **Table calcs of a measure** (`table_calc`): shares of a bar/table that sum to 100% → `percent_of_total` (the whole table by default; "share within a row" → `along: [the columns' dimension]`); "Δ to previous", "MoM %" on a line → `difference` / `percent_difference` (along the date); "running total" → `running_total`. Not with a bar's sort; KPI tiles have no table calcs.
- **Table calc functions in a calc's formula**: "place / rank" → `RANK(SUM([X]))` (ties 1, 2, 2, 4; `RANK_DENSE` → 1, 2, 2, 3; `'asc'` from the smallest); "deviation from the average" → `SUM([X]) - WINDOW_AVG(SUM([X]))`; "3-month moving average" → `WINDOW_AVG(SUM([X]), -2, 0)`; "previous period" → `LOOKUP(SUM([X]), -1)`; "running" → `RUNNING_SUM`; "left to the end" → `WINDOW_SUM(SUM([X]), 0, LAST())`; "share in a group" → `SUM([X]) / TOTAL(SUM([X]))`; a row number → `INDEX()`. Such a calc must have `compute_using: [the sheet's dimensions]`: along what to compute (the sheet's other dimensions are partitions); each sheet with this calc must have these dimensions. bar / line / area / table / heatmap only, without a bar's sort, Top N, plan and reference lines; not inside a LOD or aggregate; a calc does not refer to another table calc's calc (write the expression whole). Simple "% of total / Δ / running" stay `table_calc` of a measure.
- **A derived note under a KPI number** ("32.3 per analyst", "44% of total", a share strip under a tile): see `measures[].note` below; do not make such a number a separate tile (it changes the layout). A number that cannot be written that way → `accepted` in the case file with a reason (and "not moved" in the report). If the same value is in the book (an average per analyst = a bar's `avg` reference line), reconcile gives `elsewhere`, then `accepted` is not needed.
- **A table with a text column of a second dimension** (Analyst + Owner team) **or an order by Total**: see `rows` of two fields and `sort: {by: "total"}` below.
- **Heatmap**: cells from light to one color → `color: {scale: "sequential"}` (light gray → accent); red ↔ gray ↔ green around "zero / plan" → `color: {scale: "diverging", center: 0}` (`good: "down"` if down is good; without `center` lint C11 error); color steps in the legend → `steps: N`; a legend range "from … to …" → `min` / `max` only within the cells' values (gate). Row totals as bars to the right of a heatmap and column totals as bars above it ("hour × weekday") → `margins: {rows: "bar", cols: "bar"}`: a total is the measure over the data's rows (for AVG not the average of cells), the dashed average draws itself. A bar filled by value → the same `color: {scale: …}` on a `bar`. A heatmap without a scale: lint C10 warn.
- **Totals and an own tooltip**: a "Total" row under a table → `totals: {grand: "rows"}`, a "Total" column on the right → `"cols"`, both with a corner → `"both"`; a label other than "Total" → `label`. Group totals of a registry with two row fields → `totals.sub: [the outer dimension]` (labeled "Total"). A total is the measure over all rows of the partition, not a sum of cells: check an HTML total of AVG / COUNTD / a share by this rule, not by addition. `table` and `registry` only (a registry: `grand: rows`, all columns `style: text` without highlight); heatmaps, charts and table calc measures have no totals. A hover hint with a phrase ("Region: East — Sales 35 353") → `tooltip: "Region: <Region>\nSales: <SUM(Sales)>"`: fields in `<…>` are the sheet's dimensions (`<Region>`) or measures with an aggregation as in Tableau (`<SUM(Sales)>`, `<AVG(Profit)>`, `<COUNTD(Order)>`, `<AGG(calc)>`); a measure not on the sheet goes to the Tooltip shelf, a dimension not on the sheet is an error (it splits marks). bar / line / area / table / heatmap.
- **Finding lines, notes under KPIs, a legend line, a table of two fields**: a phrase under a block header with numbers from the data ("Busiest day: **Thu (82)**; weekend adds only 8.") → `insight: "Busiest day: **[Peak Day] ([Peak Day Closures])**; weekend adds only [Weekend Closures]."`, each number / name is an aggregate calc in `[…]`, bold in `**…**`; a leader ("top analyst") is a key "sum + name" by INCLUDE and MAX. A note under a tile's number ("44% of total", "32.3 per analyst") → `measures[].note: "[Share] of total"` (a calc `SUM([x]) / SUM([y])` with format `pct0`). A legend line of colored squares under a header → `legend: "inline"` + colors in `fields.<field>.color`. A table with two label columns on the left (analyst + team) → `rows: ["Analyst", "Owner Team"]`; rows by total → `sort: {by: "total", order: "desc"}`.
0. **A measure without numeric evidence** (a line without value labels): take the field the block's title names and write "measure chosen by title" in the report.
1. **One block → one field by evidence only.** If there are several candidates with different meanings (say, `count(osm_id)` vs `countd(osm_id)`), choose the simplest (`count` of rows) and state the choice in the report. If the meaning is not obvious, **ask the user**.
2. A KPI's measure: `count` on any non-empty column = the number of rows. Take an identifier column (`id`, `osm_id`…), not a category.
3. Do not put a numeric column in `dimension`/`rows`/`cols`/`color`: the generator rejects it.
4. Sheet names come from block titles, in Title Case, without `[]'"<>&`, unique, ≤ 100 characters.
5. KPI cards in the HTML (a big number + a label) → `"style": "tiles"`: a tile per measure, label = `label`. `style: table` only if the HTML has the KPI as a table.
   **A KPI with a delta and/or a history** (a number + "▲ 12% vs PY" / "MoM" / a sparkline under the number) → `"style": "cards"`:
   - `date`: the date field; level: the card's period (week / month / year);
   - `compare: "year"` if the HTML has "vs PY / YoY / vs last year"; else `"previous"`;
   - `good: "down"` for metrics where growth is bad (days to close, churn, costs, complaints);
   - compare numbers in the HTML with the expected of the current period: the period is the last in the data; if the HTML shows another period, write that in the report;
   - KPIs on a plain store CSV: a date with time works for `date`; `field` and `per` can be a row-level calc, not an aggregate one; average order → `{"field": "<revenue>", "per": "<order>", "per_agg": "countd", "delta": "pct"}`; a share with a change in percent, not points → `per` + `delta: "pct"`.
   - More KPI forms: a delta "▲ 5 | 1.1% vs PM" (absolute and percent) → `delta: "abs_pct"`; a delta on a pale colored plate → `delta_style: "pill"`; a history as a line (sparkline) → `history: "line"` (max and the last point are labeled, the average dashed: `history_reference`); a colored strip on a card's left → `marker: "bar"`; a line "Dec 2025 compared to Nov 2025" under the header → `period_line: true` on one KPI sheet; "Data as of / Last updated <date>" on the right of the header → `dashboard.data_as_of: "<date field>"`.
6. Bars in the HTML ordered by value (numbers at the bars are monotonic) → `"sort": "desc"`/`"asc"`. If the order is alphabetical or arbitrary, no `sort`.
   **A registry table** (rows by 1–2 dimensions, gray bars with a number in cells, highlighted bad values, sorting) → `"type": "registry"`:
   - `rows`: the rows' dimensions, the outer group first;
   - `columns`: columns in HTML order: `style: "bar"` if the cell has a bar, else `"text"`; `label`: the column's title from the HTML;
   - cell highlight by background → `highlight: {"below": X}` / `{"above": X}`; the threshold from the HTML's legend or label, if none, ask the user;
   - rows ordered by value → `sort`.
   - **Header and bar color**, under the faithful style only: a table header filled with color (white column titles on navy) → `header: {"color": "#rrggbb", "text": "#rrggbb"}`; colored bars in cells (`bar_inside`, a `track` share) not in the accent color → `bar_color: "#rrggbb"`. Take colors from the outline, not by eye: a `table` block has `header_colors.background` / `.color` (the computed style of the first `th`, or its row / `thead` if the `th` is transparent) and `bar_colors` (the fill of elements with an inline `width` in cells), `rgb(13, 58, 107)` → `#0d3a6b`. If the outline did not find the table (a div table), take the header's computed style in DevTools and the variable from `outline.palette` (`--navy`). `text` can be left out: the generator takes white or dark, whichever contrasts more. Then `lint`: C8 (the header's text on its color, a white number on `bar_color`) without errors. The color of a total row (`tfoot`) does not move: a registry's total is a gray strip.
   - **Registry columns** by the look of an HTML cell: a place number "1, 2, 3" → `style: "rank"` (a rank within the outer group, ties 1, 2, 2, 4); "21%" share of the total → `"share"`, "**21%** (230)" → `"share"` + `with_value: true`; a colored bar with a number inside → `"bar_inside"`; a bar on a gray track up to 100 % → `"track"` (one per registry, the share next to it as a separate `share` column); a colored dot with a number → `"dot"` (`good: "down"` if more = worse); a bar with a tick of the previous period / plan → `"tick"` + `base` (the tick's measure, a previous period is a calc `SUM(IF YEAR([Date]) = … THEN [Sales] END)`); a colored "▲ 12.3%" → `"delta"` + `base`; a number with a second gray line under it → `"text"` + `second`. A column's measure can be a calc. Several same lists "Top 3 by channel / country" → one registry with `repeat: [dims]` instead of `rows` and `top: {n}`; in the dashboard's grid, its name, the generator unfolds it into cells "<name> · <dim>". A share with `top` is counted from the sum of the shown rows (as in Tableau): if the HTML gives a share of everything, the report.
7. **Headers.** A block has a header only when the HTML has one:
   - `title`: the block's visible title, `subtitle`: a gray line under it (a hint, what a mark is, the period);
   - both are independent; if a block has no title in the HTML, set neither (the sheet's name is not shown on a dashboard);
   - keywords bold in the HTML are wrapped in `**` ("**Regions** Overview"); without `**` the whole title is bold;
   - the book's locale: `"locale": outline.locale` from `<html lang>` (`ru*` → `ru_RU`, otherwise and without lang → `en_US`, which can be left out). It sets number separators and month names in Desktop on any machine; an HTML in another language without `lang`: set `"locale"` by hand and say so in the report;
   - the dashboard header: `dashboard.title` from the h1, `dashboard.subtitle` from the line under it (source, "Data updated: …"). A line that JS recalculates by a filter ("North · South · 12 analysts"): take its look on page load, the same state as the filter's `default`; in the report: "the subtitle is static, it goes stale with another selection";
   - short text: if it does not fit 3 lines of the block's width, the generator refuses;
   - do not write a click hint in `subtitle`: the generator adds it from `dashboard.actions` (rule 8).
   **Color with a meaning**, by what color does in the HTML:
   - gray marks and one or two colored (an own region, leaders) → `color: {"highlight": [values]}`; a line/area also has `field`, the series' field. Take the values from the CSV as they are;
   - green/red bars by sign, "above/below plan" → `color: {"good": "up"}`; if less is good (costs, churn) → `"down"`. A delta to plan is a calc `SUM([Actual]) - SUM([Plan])`;
   - a wide gray plan bar behind a narrow actual → `plan: {"field": ...}` (without `color`);
   - a legend as colored words in a title/subtitle → in `subtitle` `{accent:East}`, `{good:above plan}`, `{bad:below plan}`; only colors the sheet draws. These sheets have no separate legend;
   - a categorical palette with a legend (each category its color) → `color: "Field"`.
   **Reference lines**: a dashed line across a chart (`stroke-dasharray`, `<line>` with a label):
   - "Average 76", "avg" → `reference: {"type": "avg"}`; "Median" → `"median"`. The label from the HTML goes to `label` ("weekday avg"), the generator adds the number. If the HTML's average is not over all marks (weekdays only), it is a calc, empty outside the needed marks, in `reference.measure`; for a stacked bar the average is over bar totals;
   - "Target 105K", "Plan", "Goal", a fixed number → `{"type": "const", "value": 105000, "label": "Target"}`; a target the user moves with a control → an integer parameter and `{"type": "param", "parameter": "Target"}`;
   - bars above average in color, below in gray → `color: {"vs": "avg"}`, in `subtitle` `{accent:above average}`;
   - a line "Average" in a KPI card's history → `history_reference: {"type": "avg"}`; history bars green/red by growth to the previous period → `history_color: "change"`;
   - more than one line per sheet only with a reason (lint I7). Check by number: `reconcile` finds "weekday avg 76" by the line's label.
   **Comparison with a benchmark**, `line` only: "the selected region vs the whole organization" (the selected line in color, the benchmark gray) → `benchmark: {"field": "Region", "select": {"parameter": "Select Region"}, "against": "all", "label": "Organization"}` (a choice by a select parameter; a fixed member → `"select": "West"`; a choice by a dashboard filter → `"select": "filter"` + a `single_dropdown` filter with one `default`, other filters `context: true`), do not set `color`, in `subtitle` `{accent:selected region}`; labels of the last values at the lines' ends → `labels: "last"`, first and last → `"ends"`; a vertical date line "Jun 1st" → `reference: {"type": "date", "value": "2025-06-01", "label": "Jun 1st"}`; a pale "target corridor" band → `{"type": "band", "from": 3000, "to": 5000, "label": "Target range"}` (`from`/`to` a number or an integer parameter); the same charts for several measures in a 2×2 grid → one sheet with `repeat: [measures]` and `columns: 2`, the legend once in its `subtitle`. A hatched difference between lines, a dashed benchmark and avg/median over a benchmark are not supported: "not moved".
   - on these sheets the generator hides the axis title and field label that repeat the block's header: name the measure and cut in `title` ("Sales **by region**"), then there are no extra labels.
8. **Cross-filter and highlight.** If a click (or hover) on a row/bar/label of one block filters or highlights others in the HTML → `dashboard.actions`. Where to look (all three, not only the code):
   - `outline.clicks`: elements with a click handler by block: `control: false` (a label, bar, cell) = an action, `control: true` (a button, tab, link) = 8b/8c, not an action; `clicks_delegated: true`: one handler on document, look at the JS;
   - the mock's notes / requirements: "click on a bar", "highlight", "cross-filter";
   - hints "click to filter", `cursor: pointer` on marks.
   A highlight in the HTML (other blocks dim) → `type: "highlight"` if the target blocks have the same field; if the targets lack the field (another cut), → `filter` by this field (highlight would find nothing there) and "highlight → filter" in the report. An action's fields are CSV columns only: a source with calcs on its axes (a heatmap) goes without `fields` (all the mark's fields).
   - `source`: the block clicked (bar, line, area, table, heatmap, registry; not a KPI);
   - `targets`: the blocks that change; if all others change, leave out (`all` by default);
   - `fields`: only if the source block has several dimensions and one should filter;
   - `on: "hover"` if the filter works on hover;
   - `clear: "exclude"` if target blocks are empty until something is selected (a drill-down by click);
   - `hint`: the hint's text from the HTML; without it, "Click to filter" / "Hover to filter" after the block's subtitle.
   If clicks in the HTML filter nothing, add no actions. A click on data with no `actions` → `lint` A1 (warn): move it or write it in gaps "Lost interactivity" with a reason.
8a. **Dates and a period filter.**
   - `profile` determines the CSV's date format: the line "DD.MM.YYYY in the CSV" and `text-file locale` in the output's head. In the spec dates are always `YYYY-MM-DD`, whatever the CSV's format.
   - If `profile`/`build` refuses (ambiguous `01/02/2024`, mixed formats, `DD.MM` and `MM/DD` in one file), do not guess dates: ask the user or ask for an export in YYYY-MM-DD and write that in the report.
   - A datetime field (`2025-03-15 14:30`) goes on an axis as a date (`level` by the axis labels). Do not use it in `calcs`, the generator refuses.
   - A date range "from … to …" → `{"field": <date>, "mode": "range", "min": ..., "max": ...}`. Take the bounds from values shown in the HTML. If the HTML shows the whole period of the data ("All time", an empty picker), no `min`/`max`: then new dates fall in the filter too.
   - A button/item "Last N days/weeks/months/quarters/years", "This month" → `{"mode": "relative", "period": ..., "last": N}` (This month = `last: 1`). The anchor's period counts whole: "Last 3 months" with data up to July 2 = May–July.
   - `anchor`: if the HTML counts from a specific date ("as of 2025-06-30", "Data updated: …"), write it. Otherwise leave out: the last date in the data becomes the anchor. If the HTML explicitly counts from "today", write in the report "the period is from the last date in the data, not from today".
   - "Month to date", "Previous month", a choice of only a start or only an end: not supported yet (the report).
   - Date cards stand only in the dashboard's header: `dashboard.title` (or subtitle) is needed and no `sidebar`. A range by date 242px, by datetime 300px, relative 142px. If the width is short, the generator says so; then a wider dashboard or fewer filters.
   - Compare KPI numbers in the HTML with expected **after** the period filter: they must match at the same bounds.
8b. **Metric switches, Top N, the date level.** A control in the HTML (`<select>`, a button group, a slider) that changes the measure, the number of bars or the time detail, rather than filtering rows → `parameters`.
   - **Metric** ("Sales / Profit / Units" changes all blocks) → `{"name": "Metric", "type": "string", "values": [labels from the HTML], "default": the one selected on load}` and a calc `CASE [Metric] WHEN "Sales" THEN SUM([Sales]) WHEN "Profit" THEN SUM([Profit]) ... END`: each value has its branch (without `ELSE` the generator requires all). This calc is the `measure` of the blocks that switch. Replace the measure's name in a block's title with `[Metric]`: "Top products by [Metric]" shows the selected value.
   - **Top N**: "Top 10 …" in the HTML, bars cut → a bar's `"top": {"n": 10}`. If N is chosen (select 5/10/20, a slider) → an integer parameter `{"type": "integer", "range": {"min": 5, "max": 20, "step": 5}, "default": 10}` and `"top": {"n": "Top N"}`, `[Top N]` in the title. Top N is counted by the bar's measure over all data, before dimension filters (as in Tableau); if the HTML shows the top within a selection (a region, a team), that filter has `context: true`. A field with a dashboard filter (`filters`) cannot get a Top N: a sheet has one filter per field. If the HTML has more than 12 bars without a Top N, lint I4 asks to add it (N ≤ 12).
   - **Date level** (Week / Month / Quarter on a line) → a string parameter with values from `day, week, month, quarter, year` (lower case, as in DATETRUNC), a calc `DATETRUNC([Period], [Date])`, a line's `"date": {"field": <this calc>, "level": "day"}`. Do not move the HTML's button labels ("Weekly") to values: the value is the level.
   - Values without `"`. Compare KPI and bar numbers in the HTML with expected at `default`; another value: `expected.compute(spec, csv, {"Metric": "Profit"})`.
   - Parameter cards stand in the dashboard's header after filters (`dashboard.title` is needed, no `sidebar`): a list is a 142px dropdown, a range is a slider. Short of width → a wider dashboard.
   - The generator does not let through a parameter that affects nothing. Not supported (the report): value labels different from the values (aliases), a value "from a field on open", Top N on a line/table and Bottom N, real/date parameters.
8c. **Interactivity.** A click on an element changes the state of the whole dashboard, rather than filtering by a mark.
   - **Clickable metrics** ("Click a metric to filter the views", a list or row of metrics, the selected one highlighted) → a string parameter `Metric` (8b, a CASE calc) + a sheet `{"type": "buttons", "parameter": "Metric", "arrange": "column"}` in the cell where the HTML has the list; a button per value, the current one in the accent color. Then no parameter card in the header (`control` defaults to `none`). A click on a KPI tile itself is not moved yet: buttons next to it, "simplified" in the report.
   - **Period tabs** ("L6M / L12M / All", "3M / 6M / 12M / All") → a parameter `{"name": "Period", "type": "string", "values": ["L6M", "L12M", "All"], "default": the selected one, "period": {"field": <date>}}` + a sheet `buttons` with `arrange: "row"`. Values only `L<N>` + D/W/M/Q/Y and `All`: "L6M" = 6 whole months up to the data's last date inclusive (like relative). "YTD", "MTD", "Custom": not supported, the report. The period filters all sheets; Top N and FIXED are counted before it (Tableau's order).
   - **A view switch** (chart/table icons, "Chart | Table", area/bar) → a string parameter with view values + a sheet `{"type": "switch", "parameter": "View", "views": {"Chart": "<sheet>", "Table": "<sheet>"}}` in the grid instead of the sheets themselves; views are bar/line/area/table/heatmap/registry, standing nowhere else in the grid. The control: a sheet `buttons` by the same parameter or `"control": "radio"` of the parameter (radio buttons in the header). A toggle between tables ("Top Won | Top Lost") is the same switch with registry views; short values ("Won", "Lost"): a radio card is ~140px, a long value is cut to "..". A switch's parameter card stands only on its switch's dashboard. In a book with several sources a switch gets the `"datasource"` of its views (all views of one source); no buttons there yet, only `"control": "radio"`.
   - A radio instead of a dropdown (`<input type=radio>` as a group) on any string parameter → `"control": "radio"`; the header row gets taller by a line per value.
   - Compare numbers at the default values; the HTML shows another metric or period → in `reconcile.json` `"parameters": {"Metric": "Profit"}`. All values at once: `expected.by_value(spec, csv, "Metric")`.
9. Not supported yet (always in the report if the HTML has it): a dark theme, unit conversion, a numeric field as an axis.

## 3. Layout
- The tree `outline.layout` → `dashboard.grid`. Each top-level row of `rows` becomes a grid row, `cols` inside a row give cells left to right.
- Columns with their own rows inside → **a group**: a cell `{"rows": [[…], …], "width": N, "row_heights": [...]}` (up to 3 levels of nesting), do not flatten. Archetypes:
  - **A**: a KPI column on the left at full height → `[[{"sheet": "KPI"}, {"rows": [...], "width": 2}]]`, the KPI has `"arrange": "column"`;
  - **B**: a KPI strip on top → the grid's first row;
  - **C**: a left panel with a title, filters, legends (no charts) → `"sidebar": true`, do not move the panel itself to the grid.
  - **Shell.** A left panel filled with the brand color → `"sidebar": {"color": "#rrggbb"}`: a letter logo ("C calls.") → `logo: {text}`, an image → `logo: {image}` (a file next to the spec); "Download PDF / PPT / Image" buttons → `download: ["pdf", "ppt", "image"]`; "Created by … / Data source: …" at the bottom → `footer`. A dark full-width strip over the header (the app's name, "Welcome, <name>") → `dashboard.topbar: {color, title, welcome: true}`; do not move the name from the HTML, FULLNAME() fills it in. The brand color goes only here, not on marks; do not move a "Reset Filters" button: 2025.1 has no reliable form for it, it goes to "not moved" in §5 with this reason. A color legend does not go in a brand panel: color with a meaning and colored words in a block's subtitle. Then `lint`: C8 (text contrast) without errors.
  - **Cards.** The card theme is the default: do not write `theme`. `"theme": "flat"` in `dashboard` is the plain look without cards (a white page, blocks without borders): only if the HTML is like that and the user asks, and always with `sidebar`, `topbar`, `block_headers: false`. A page font of Arial / Helvetica → `"theme_font": "Arial"` (another first in `font-family`, say Segoe UI: do not set, the report). KPIs on one plate with vertical lines between numbers → `arrange: "strip"`; KPIs on separate plates in a row, also one KPI sheet with `strip` (one card with dividers), "simplified" in the report. The main mark color of the HTML is not blue (a highlight, a scale's end, map circles of one color) → `"accent": "#rrggbb"` in `dashboard`: replaces `#4e79a7` across the book. Take the color from the outline (`palette`), not by eye; `lint` C7 warn: the accent is close to good/bad, C8 error: a white number on the accent (`bar_inside`) is not readable. The theme has no `sidebar` or `topbar` yet (the generator refuses): with an HTML shell do not move the cards, write it under "not moved". A card takes 21px on each side (margin 8 + border 1 + padding 12): if the generator says "too short", give the row a bigger `row_heights` weight.
  - **Several tabs / pages.** Tabs, a menu or buttons that switch HTML pages (or several HTML files of one report) → `"dashboards": [{…as dashboard…}, …]` instead of `dashboard` (the first opens with the book) + `"nav": {"style": "tabs"}`, a row of tabs on top, or `"sidebar"`, buttons in the side panel (the dashboards need `sidebar`); button labels from the HTML → `nav.items: [{dashboard, label}]`, each dashboard in nav. Sheets are shared: one sheet can stand on several dashboards (except `registry`). The shell (`sidebar`, `topbar`, `theme`, `theme_font`, `accent`, `data_as_of`) is the same in all. Filters are shared across the book: a card on each dashboard, a choice on one changes all; actions stay within their dashboard. The outline may not see hidden tabs: compare their numbers separately (reconcile by the selected tab).
- KPI blocks of one row → **one** KPI sheet (`style: tiles` or `cards`) in one cell; tiles and cards share the cell equally. KPIs in a column → `"arrange": "column"`.
- Unequal column widths: a cell `{"sheet": "...", "width": N}`, where N is the rounded ratio of frame widths (1–12, say 1:2). Unequal row heights: `dashboard.row_heights` (one weight per grid row, say `[1, 3]` for a narrow KPI row). The generator sets spacing itself, so a row of KPI tiles needs at least ~110px; if the row is small, the build fails with "too short for a KPI tile": raise its weight.
- The dashboard's size: by content, not by window. `outline.page` is the screenshot window's size: width = the wrapper's frame (or the union of block frames + margins), rounded to a width of D1; height by content, then enough for tables and registries to fit without scrolling (≈ N rows × 20px, in the cards theme × 30px, + the column header). Within 400–4000.

## 4. Build and check
```bash
python -m tbuilder build specs/<name>.json -o out/<name>.twbx
```
- A schema/data/gate error → fix the spec by the error's text and repeat. Repeat the fix cycle **no more than 3 times**, then show the error to the user.
- Open the `.twbx` in Tableau Desktop and compare with `page.png`. KPI numbers must match the HTML (given the units in the report).
- **Design**: `python -m tbuilder lint specs/<name>.json` (rules in context/design-rules.md) → 0 errors, each warn with a reason. Then the agent `dashboard-designer` (.claude/agents/dashboard-designer.md): edits the spec to the rules without changing numbers, and checks a screenshot in Desktop (spacing, data-ink).
- **One command** (skill `/to-tableau`): `python -m tbuilder to-tableau-check <spec.json> <page.html> --case <case>.json -o <x>.twbx`: lint → build (gate) → Desktop → drawn → resave → reconcile, verdict OK / FAIL (the book is deleted) / INCOMPLETE (a step did not run: `--no-desktop`, no Chrome). View edits: `to-tableau-preview <spec.json> -o <x>.twbx` (no reconcile, not acceptance, the book is `<x>_preview.twbx`), the final run is one full check (the queue `out/desktop-queue.md` only if other sessions work).
- **HTML ↔ result reconciliation**: `python -m tbuilder reconcile specs/<name>.json <page.html> --case <case>.json` → OK. Each number of the page: `matched` / `elsewhere` (pass), `mismatch` (a wrong binding: fix the spec), `missing` (the number is not reproduced). In the case file `state` = the filter selection the HTML shows (only fields of `filters`; on a filter with `default` the state must match it; better set `default` at once, then no state), `accepted` = numbers not moved, each with a reason; the same reasons as in report §5 "not moved". Accept a `mismatch` only with a reason that explains the difference, not hides it. "Mon" / "19 Mon" / dates / dashes link by themselves (aliases are for labels in the book, not for reconciliation); numbers of canvas charts (Chart.js, ECharts, data attributes) are checked by the chart's data, a canvas without data is `unverified`; each value of a select / filter buttons is checked as a separate state (options with other text: `options` in the case file); `ambiguous` / `unverified` do not fail but go to the report.

## 5. Report to the user
- what moved and how (block → sheet → field/aggregate);
- what is simplified (with a reason);
- what did not move (with a reason);
- which choices were made without clear evidence;
- **lost interactivity**, a required section of gaps.md: each click on data from `outline.clicks` and notes → which action carries it (`source` → targets, filter / highlight) or why it did not move. No clicks: a line "no clicks on data in the mock".
